The arithmetic flaw and its repair

Sparse polynomials store only coefficients thought to be nonzero. The earlier helper retained a coefficient with if v != 0. For an Arb ball containing zero and nonzero values, both v == 0 and v != 0 can be false. These tests certify relations between uncertain quantities; they are not logical complements. Consequently, the old cleanup could discard a coefficient whose true value was nonzero. The simplest example is a ball centered at zero containing 1/2: turning that coefficient into an omitted term incorrectly replaces its allowed value 1/2 by zero.

The failure was observed in the actual new uniform-field construction: ten uncertain coefficients were dropped across nine cleanup calls. The audit did not establish observed corruption of every historical point result. Nevertheless, the old full point certificates could not be relied upon: their local enclosure engine was unsound, and their independent integrations reused that same arithmetic. Hash agreement and two implementations sharing a bug do not establish enclosure validity.

The new version removes only a coefficient certified exactly zero, using is_zero() for finite Arb balls, and rejects nonfinite coefficients. All old sources and receipts are preserved.
